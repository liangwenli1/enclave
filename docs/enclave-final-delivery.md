# Enclave 交付说明

> 卖法和客户用法对齐 AdsPower / GoLogin / Multilogin 这一类：
> **官网下载桌面安装包 + 账号订阅解锁额度。内核跑在客户自己的电脑上。**
> 不是服务端开 Chrome、客户端只看网页。

更新于 2026-09-20。这份文件同时是**交付合同**和**当前进度**：
"已交付"一栏只写代码里真的做到的事，做不到的写在"未交付"。

### 1.2 客户用法（1.0 必须是这条）

1. 打开官网，注册（免费档立即开通）。
2. 下载安装包，**核对 SHA256**，安装。
3. 打开本机工作台，点「登录」，在弹出的官网页面里登录并点「允许」。不登录不能用；额度以服务器为准。
4. 「内核管理」页下载一个版本：下载 → 校验压缩包 → 解压 → **记录实际可执行文件的哈希**。
   清单里可以有多个版本并存，各自下载、各自删除；每个环境绑定一个版本。
5. 新建环境 → 配代理 → 锁定画像 → 启动。
6. **本机弹出独立内核窗口。** Cookie / 指纹 / 出口只属于这个环境。
7. 实验室采集的是该内核窗口，不是工作台自己的页面。
8. 换电脑：安装、登录、导入环境包（`.enclave.json`）。同一个环境在两台电脑上都有时，同一时刻只能开一边。

失败必须拒启并显示原因码：`KERNEL_HASH_MISMATCH` / `KERNEL_UNTRUSTED_SOURCE` /
`KERNEL_CHANNEL_BLOCKED` / `SANDBOX_UNAVAILABLE` / `CDP_HANDSHAKE_FAILED` /
`HOST_UNAVAILABLE` / `VAULT_LOCKED` / `PROXY_PASSWORD_MISSING` / `PROXY_UNREACHABLE` /
`PROXY_AUTH_FAILED` / `PROXY_REFUSED` / `PLAN_CONCURRENT_LIMIT` /
`SPAWN_FAILED` / `SANDBOX_DISABLED_BLOCKED`。
**禁止绿灯假 Running。**

### 1.3 明确不是交付物

- `npm run dev` / vite 预览
- 把工作台当网站卖、"客户打开你们的网页，Chrome 在你们服务器里"
- 把 `data/kernels/` 打进镜像分发
- 任何"保证过某站风控"的承诺

## 2. 商业结构

### 2.1 档位

| 档 | 环境数 | 同时运行 | 席位 | 每人几台电脑 | 本机 API | 价格 |
|---|---|---|---|---|---|---|
| Solo Free | 3 | 1 | 1 人 | 1 | 关 | 免费，注册即开通 |
| Solo | 50 | 3 | 1 人 | 1 | 只读 | 报价 |
| Pro | 200 | 8 | 1 人 | 2 | 完整 | 报价 |
| Team | 200 | 8 | 6 人 | 1 | 完整 | 报价 |

档位**只在一处定义**：`enclave-www` 仓库的 `api/internal/license/license.go`。客户端里没有档位表，
显示的数字是服务器刚回答的；官网账号页从 `/api/plans` 取。
窗口同步尚未实现，所以不在表里；规格见 [TODO.md](../TODO.md)。团队席位见 4.19。
安装包不收费。内核安全更新对所有档位开放，不锁在高档。

付费走 Creem（官网账号页订阅，Webhook 改档）；管理员也可以在官网后台手动改档。两种都是改数据库，工作台下一次问到就是新的。

### 2.2 额度怎么生效：服务器说了算

```
工作台点「登录」 ──> 本机服务生成 verifier / challenge，在系统浏览器里打开官网 /device
官网（已登录）点「允许」 ──> 一次性授权码 ──> enclave://auth?code=… 跳回工作台
本机服务：授权码 + verifier ──> 服务器 ──> 设备令牌（存进系统钥匙串）
之后每次新建 / 启动 / 心跳：本机服务 ──设备令牌──> 服务器
```

- **没有"本机凭据"**：不签发、不缓存任何"几天内有效"的许可证。数据库里此刻是什么档，就是什么档；
  官网那边订阅一变，下一次新建或启动就按新的算，不用同步、不用重新登录。
- **要登录才能用**。注册即免费档。密码只在官网输入，工作台和本机服务都不经手。
- **环境名额由服务器数**，账号下所有电脑合计。服务器只登记环境的 id、名字和内核版本；
  指纹、代理、Cookie 不上传。新建、复制、导入、从回收站恢复都要先登记成功。
- **启动前申请租约**：同时运行数按账号合计；同一个环境同一时刻只能在一台电脑上打开（`PROFILE_LOCKED`）。
  本机服务每 20 秒续一次，服务器 60 秒没收到就释放。续约时发现租约已经归别人、或者这台电脑被解绑，
  本机服务会停掉那个环境。只是暂时断网不会停：已经在跑的浏览器照常用，网回来自动续上。
- **连不上服务器就不能新建、不能启动**（`CLOUD_UNREACHABLE`）。这是"实时一致"的代价，已明确接受。
- 降档后登记数超过名额：只有最早建的那几个能启动，其余要续订或清理后才能用。
- 和服务器说话的只有本机服务。工作台页面碰不到设备令牌，也不直接连外网（CSP 只放行本机服务）。
- 脚本用的本机 API 和工作台走同一道闸：档位由本机服务自己问服务器，不听页面的。

软件在用户机器上，足够熟练的用户可以改本机程序，这一点没有变。变的是：额度不再由本机那份代码说了算——
改掉工作台里的数字没有用，名额和并发是服务器数的。

## 3. 架构（发行形态）

```
客户电脑
┌───────────────────────────────────────────────┐
│ Enclave.exe (Tauri)                           │
│  ├─ 生成 32 字节 OsRng 令牌                    │
│  ├─ 启动 enclave-host（sidecar，带令牌）       │
│  └─ initialization_script 注入同一个令牌        │
│                                               │
│  ┌─────────────┐   Bearer 令牌                 │
│  │ React 工作台 │ ──────────────┐               │
│  └─────────────┘               ▼               │
│                      enclave-host 127.0.0.1    │
│                      准入 / spawn / CDP / 回收  │
│                               │ spawn          │
│                      fingerprint-chromium      │
│                      user-data 独立            │
└───────────────────────────────────────────────┘
        │ 只有本机服务出这条线：登录、额度、环境名额、运行租约、内核清单
        ▼
  云端 API（HTTPS。只有账号、档位、环境的名字；没有指纹、代理、Cookie）
```

数据都在客户机：环境定义与画像在工作台数据目录，Cookie 在各环境
`profiles/env_*/user-data/`，代理密码在 AES-GCM 保险箱，内核在 `data/kernels/`。

## 4. 已交付（逐条可验证）

### 4.1 本机接口不再任人调用

之前：桌面壳用 `ENCLAVE_ALLOW_LOOPBACK_NO_AUTH=1` 启动 Host，CORS 是 `*`，
**任何网页都能 POST `127.0.0.1:17891` 启动环境、枚举运行态、改写环境的默认搜索引擎。**

现在（`crates/host/src/main.rs`）：

- 跳过鉴权的开关**整个删掉**，代码里不存在这条路径。
- 令牌是 32 字节 `OsRng`（之前是 `DefaultHasher(时间+pid)`，可枚举），文件权限 0600，定长比较。
- CORS 只放行工作台自身来源；其他 Origin 直接 403。
- `Host` 头必须是回环地址，挡 DNS rebinding。
- 端口可配，**地址不可配**：永远只绑 127.0.0.1。
- `/v1/health` 只回 `{ok:true}`，不再泄露内核版本和本机能力。

### 4.2 校验的是真正被执行的文件

之前：只校验下载的压缩包；解压目录里已有 chrome 就跳过解压，所以一个被替换过的
可执行文件会被直接沿用，界面还显示"已准入"。

现在（`crates/host/src/kernel.rs`）：

- 准入时**必然重新解压**，然后对可执行文件单独算 sha256，连同大小和修改时间记下来。
- 每次启动前核对可执行文件：本进程第一次做全量 sha256，之后比对大小/修改时间，
  任何一项对不上就升级成全量校验，不符 → `KERNEL_HASH_MISMATCH` 拒启。
- `status.json` 里记的"已准入"不再被无条件相信：文件对不上就改回错误态。
- 运行态里记录的 sha256 是可执行文件的哈希，不再是压缩包的。

### 4.3 内核通道会拦

清单里 `channel != stable` 的内核（当前 win-x64 / mac-arm64）需要用户在安全中心
明确勾选"允许使用预览通道的内核"，否则准入和启动都返回 `KERNEL_CHANNEL_BLOCKED`。
之前代码完全不看通道，只要有哈希就用。

### 4.4 环境、代理、代理密码的真相在本机服务里

之前：环境和代理只存在工作台页面的 localStorage 里，代理密码在页面里用主密码加密。页面不开，谁也碰不到这些数据，
更谈不上加密后同步；而且不设主密码就存不了代理密码，每次打开工作台都要解锁。

现在（`crates/host/src/store.rs`、`vault.rs`、`keychain.rs`）：

- 环境和代理存在本机服务的 sqlite（`data/store.db`）里，页面是它的界面：登录后读一次，之后每次改动写穿过去
  （同一条记录短时间内的多次改动合成一次写；没存上会在界面底部一直提示）。页面的 localStorage 里不再有环境和代理。
- **一把随机的 256 位数据密钥**加密代理密码（AES-256-GCM，附加认证数据里带着条目 id——把 A 的密文挪给 B 解不开）。
  它平时放在系统钥匙串里（Windows 凭据管理器 / macOS 钥匙串），由操作系统账号保护：**不用设口令、不用记口令、不用每次解锁**。
  之后的端到端加密同步用的也是这把钥匙。
- **代理密码只进不出**：页面可以存、可以删、可以知道"有没有"，没有任何接口把明文交回页面。
  启动环境时页面只说"用哪个代理"，地址和密码由本机服务自己取出来交给代理桥。
  要带到另一台电脑，只能用导出口令加密后带走——加密和解密都在本机服务里做，格式和以前页面里用 WebCrypto 导出的包一致
  （有一条测试用真实的 WebCrypto 密文钉着）。
- **应用锁是可选的**，给共用同一个系统账号的人用。开了之后数据密钥不再放钥匙串，而是用口令（Argon2id，64 MiB、3 轮）包一层存在
  `lock.json` 里；每次打开工作台要输口令，锁着时带密码的代理用不了（`VAULT_LOCKED`）、密码存不了也导不出。
  忘了口令只能重置：换一把新钥匙，保存过的代理密码清空，环境和代理本身不受影响。
- 启动时代理这一关的原因码都由本机服务给：`VAULT_LOCKED`、`PROXY_PASSWORD_MISSING`（要账号却没有密码——不会拿空密码去连）、
  `PROXY_INVALID`（绑定的代理已经不存在）。

用真内核在容器里验证过：密码读不回来、`store.db` 里搜不到明文、没存密码拒启、密码不对由代理报 `PROXY_AUTH_FAILED`、
应用锁开 / 锁 / 错口令 / 对口令 / 导出导入 / 重置。界面端到端：建代理存密码 → 整页重载后数据从本机服务回来 →
页面的 localStorage 里没有密码、没有环境 → 应用锁锁屏 → 删代理时密码一起删、环境解绑。

### 4.5 账号与订阅真的通了

云端 API（`enclave-www/api`）是 Go + Gin + PostgreSQL + Redis：

- 注册、登录（scrypt 密码哈希）、会话 cookie、登录限流。
- 设备绑定与设备数上限；官网可解绑。
- 订阅过期的账号当场按免费档算。Ed25519 只用来给内核清单签名。
- 升级申请与联系表单落库，运维用 `x-admin-token` 改档。
- 不开 CORS：调用 `/v1/*` 的是本机服务，不是浏览器页面。

之前 `setMyLicenseFn` 允许任何登录用户把自己改成 Pro —— 那个接口和整套
better-auth / Postgres 脚手架已删除。

### 4.6 桌面端不再依赖打不出来的服务端

之前工作台是 TanStack Start SSR 应用：登录和额度走 `createServerFn` → 同源 `/api/*`。
MSI 是纯静态包，没有 `/api`，所以**装完之后登录必然失败**，代码里甚至有注释承认这点。

现在工作台是纯前端 SPA：只跟本机 Host 说话，开发和打包后同一条链路；和服务器说话的是 Host。
顺带删掉了模板残留：`grok-pwa` 插件与其两万行测试、`app-data` 连接器、
`multiplayer/p2p.ts`（570 行零引用）、better-auth / PGLite / Neon / Nitro / migrations、
以及三份官网拷贝里的两份。

### 4.7 Tauri 壳收紧

- capabilities 从 `shell:allow-spawn` + `shell:allow-execute` 收到只剩 `core:default`
  —— 页面不再有任何执行外部程序的能力（sidecar 由 Rust 侧启动）。
- CSP 从 `null` 改成实际策略。
- 窗口在 Rust 里创建，注入令牌的脚本先于页面任何代码执行。

### 4.8 环境导出 / 导入

`.enclave.json` 带走环境定义、画像、代理和搜索引擎配置。
**Cookie、缓存、浏览记录不在里面**，界面和文档都写明。
代理密码只有填了导出口令才会带上，用该口令单独 PBKDF2+AES-GCM 加密。
导入时受当前档位环境数上限约束。

### 4.9 界面

官网与工作台统一到一套设计系统（[DESIGN.md](../DESIGN.md)，源自 ClickHouse 的
近纯黑 + 电光黄）。所有 token 只定义一次，两边共用。

同时按"用户不需要看到的东西一律不出现"清理了界面：

- 删掉引导里的"选择档位"（那等于让用户自己发许可证）。
- 原来的 `apiEnabled` 开关打开后什么也不会发生；现在它背后是真的本机 API（见 4.10）。
- 删掉工作台里的出口 IP 探测（它探的是本机网络，不是环境出口，会让人看错；
  而且那是一个发往第三方的请求）。
- 内部状态词（`admitted` / `hash_mismatch`）换成中文，并给出下一步怎么做。
- 删掉"没有回滚版本"这种给不出原因的灰按钮、空的选择框、模板遗留页面。

### 4.10 本机 API（给脚本用）

同一个 Host、同一个端口，不是第二个服务。路径 `/api/v1/*`，凭据是独立的 API 令牌
（Host 用 OsRng 生成，0600 落盘，可重置），和工作台令牌互不通用。

- 默认关；免费档开不了；Solo 只能 GET；Pro / Team 可以启动和停止。
- 带 `Origin` 头的请求一律拒绝 —— 脚本从不带，网页必然带。
- 工作台把每个环境的启动参数推给 Host，**只放内存**（里面有带密码的代理地址）。
  代理密码在锁着的保险箱里的环境不推，脚本因此无法让它以本机网络出网。
- 同时运行上限对 API 同样生效；启动走的是和工作台同一个 `run_start`。

在真实运行的 Host 上用 curl 验证过 13 种情况，并在真浏览器里走通了
「登录 → 验签 → 开启 → 用界面上的令牌以脚本身份列出环境」。

### 4.11 测试与 CI

之前：Rust 测试 0 个，没有 CI，`npm test` 跑的基本是模板管道。

现在：

- `cargo test -p enclave-host`：flag 白名单（默认拒绝、调试端口不能离开回环、
  隔离破坏类 flag 拒绝、环境自己管的开关——数据目录、代理、画像、语言时区——不能在额外参数里改写；
  规则只有 Host 这一份，工作台的参数页经 `/v1/flags/classify` 来问）、令牌长度与定长比较、来源名单、API 档位权限、进程组信号只打到目标（不会再出现 `kill -1`）、环境 id 不能逃出数据目录。
- `cargo test` 里的 cloud 用例：服务器地址只认 https（回环例外）、授权码形状、challenge 算法与服务器一致、
  设备令牌进出系统钥匙串（在 Windows / macOS 的 CI 上测的是真钥匙串）、没登录和连不上时一律不放行。
- `npm test`：深链接只认 `enclave://auth?code=…`、断网时不拿旧数字冒充额度。
- `enclave-www`：`go test ./...`，加 `scripts/e2e-desktop.sh` 对着整套 compose 跑 38 项
  （并发新建不超额、两台电脑抢同一个环境、租约过期接手、解绑、降档……），CI 里每次都跑。
- `.github/workflows/ci.yml`：三块分别构建测试，外加"二进制和运行时数据不得进仓库"的检查。

### 4.12 多内核版本

之前：整个系统只认"这个平台的那一个内核"，环境里的内核字段是个永远相同的常量，换内核只能重装。

现在：

- **内核分两类，每一类有自己的一串版本**：Chromium 类（fingerprint-chromium）和 Firefox 类（Camoufox）。
  清单里每条记录带 `engine`；每一类只认自己上游项目的 GitHub Release 目录，类和构建 id 对不上、或者地址指到另一类的上游去，
  签名再对也不收。版本号允许带预发布标记（`152.0.4-beta.30`），仍然不许出现路径成分。
  每一类有自己的默认版本；环境建好之后只能在同一类里换版本。
- Host 按版本管理内核：每个版本有自己的压缩包、解压目录和准入记录，互不影响，可以同时下载、同时运行。
  可执行文件按类、按平台找（三个平台的包都实际看过目录）：Firefox 类是 `camoufox-bin` / `camoufox.exe` /
  `Camoufox.app/Contents/MacOS/camoufox`；macOS 上的 zip 用 `ditto` 解，保留签名。
- 环境绑定一个内核版本（`kernelVersion`），**不会自动跟着新版本走**。换内核等于换浏览器版本，
  网站会看到这台设备升级或降级了，所以只能由用户在环境详情页自己改；画像里报的浏览器版本跟着一起改，
  两者对不上时「一致性」会报出来。
- 启动时用的就是环境绑定的那个版本：没下载、或者已经不在清单里，拒启并说明原因，不会悄悄换成别的版本。
- 删除一个版本会清掉压缩包、解压目录和准入记录。还有环境在用它运行时 Host 拒绝删除（`KERNEL_IN_USE`）。

版本从哪来：

- 安装包自带的清单，永远可信、永远在。
- 厂商远程上架的（`enclave-www` 仓库 `docs/deploy.md`「上架一个内核版本」）。清单由云端 API 用它的 Ed25519 私钥签名，
  **本机服务自己去取、自己验签**，页面不经手；签的内容带域前缀。
  验过签还要过三道：下载地址规整后必须在上游项目的 GitHub Release 之下、不接受比已接受的更旧的清单
  （防回放）、版本号和文件名不能带路径成分。落盘的清单下次启动会重新验一遍。
- 厂商下架的版本：已经下载的照常能用、标"已下架"、不能再下载；没下载的直接消失。

### 4.13 本地代理桥

之前：代理地址连同账号密码直接写进内核的 `--proxy-server`。实测 Chromium 不接受这种写法——
请求根本不会发出去——也不支持 SOCKS5 认证，所以**所有需要账号密码的代理其实都用不了**；
代理通不通也没人检查，不通时环境照样显示"运行中"。

现在（`crates/host/src/bridge.rs`，Tokio + tokio-socks）：

- 每个带代理的环境在 127.0.0.1 上有一个只属于它的 SOCKS5 入口，浏览器只认识这个入口；
  向上游（HTTP / HTTPS / SOCKS5）的认证由 Host 完成。账号密码不出现在浏览器的命令行里。
- 域名原样交给上游解析，并用 `--host-resolver-rules` 禁掉本机 DNS 查询（含预解析）；
  只做 TCP，UDP 关联一律拒绝。
- 启动前先经这条路探一次。失败就拒启并给出原因：`PROXY_UNREACHABLE` / `PROXY_AUTH_FAILED` /
  `PROXY_REFUSED` / `PROXY_INVALID`。
- 探测同时拿到出口 IP、国家、城市和时区。环境开着"时区和语言跟着代理出口走"（默认开）时，
  内核用出口所在的时区和当地的浏览器语言启动（见 4.14），画像同步改成实际用的那一套。
  查 IP 的公开服务都不通时照常启动，只是不对齐；可以用 `ENCLAVE_IP_ECHO` 换成自己的服务。
- 桥和环境同生共死：停止、浏览器自己退出，入口和经过它的连接一起关。Host 重启后，
  靠桥上网的旧浏览器会被关掉而不是接管——它只认那个已经关掉的本机端口，不会绕过代理直连。

用真内核在容器里验证过：错密码、死代理各自报对原因；正确账号下上游代理收到的是未解析的域名且认证通过；
浏览器里 `Intl` 报的时区是出口所在的时区；停止后入口端口关闭。

### 4.14 成套指纹预设

风控看的不是某一项像不像真的，而是各项之间矛盾不矛盾。之前屏幕、核数是随机抽的，和平台不挂钩
（Windows 环境会抽到 MacBook 专属的 1512×982）；时区改成东京，语言还留着 en-US。

**先量了内核到底能做什么**（fingerprint-chromium 148，容器里带虚拟显示器实测）：

| 项 | 结论 |
|---|---|
| 平台、系统版本、品牌、核数、时区、语言 | 按启动参数生效 |
| 内存大小、Canvas / 文字测量 / ClientRects 噪声 | 由种子决定，换种子就变 |
| **屏幕分辨率、缩放** | **改不了**。二进制里有 `--fingerprint-screen-width/height`、`--fingerprint-device-scale-factor`，传了不生效，网页看到的始终是真实显示器 |
| Intl 区域（日期、数字的格式） | Linux 上只看 `LANGUAGE` 环境变量，不看 `--lang`：只传 `--lang=de` 时 `navigator.language` 是 de-DE 而 Intl 还是 en-US。Windows 上 `--lang` 就够；macOS 取系统设置，启动参数改不了 |

据此：

- **地区表只有一份**（`src/lib/regions.json`，46 个国家）：国家 ↔ 时区 + `navigator.language` + `navigator.languages`。
  工作台的下拉框和本机服务读的是同一个文件。时区和语言永远成对改，界面上不再有能单独填的语言框。
- **语言跟着出口国家走**：原来只有时区跟。现在本机服务按出口的两位国家代码查表，时区、`--lang`、`--accept-lang`
  一起换，Linux 上同时设 `LANGUAGE`，让 Intl 也对上。表里没有的国家只对齐时区，语言不动，一致性检查会说明。
  逐环境可关（`followExit`）。
- **核数按平台成组**：macOS 只有 Apple 芯片的档位（8 核起），Windows 从 4 核到 24 核。换平台时核数落到新平台真实存在的档位上。
  同一个种子、同一个平台得到的永远是同一套。
- **「屏幕」改叫窗口大小**（`profile.window`），因为它从来只是窗口大小。只列出放得进这台电脑屏幕的；
  从大屏电脑导过来的环境，启动前收进屏幕以内——窗口比屏幕大在真机上不会出现。
  指纹页明说：屏幕分辨率来自这台电脑，同一台电脑上所有环境相同。
- **Canvas 可以选「加噪声」或「真实」**（Chromium 类）。实测：噪声跟着种子走，同一个种子跨重启不变、换种子就变；
  `--disable-spoofing=canvas` 之后和不带 `--fingerprint` 时完全一样，也就是这台电脑的真实值。
  两种都有人用（Multilogin 默认真实，AdsPower 默认加噪声），所以交给用户选，默认加噪声。
- **一致性检查用实测值**（`src/lib/consistency.ts`）：时区与语言是不是一对、出口国家与地区、平台上少见的核数、
  窗口与屏幕；内核窗口里再核对实际语言、`navigator.language` 与 Intl、UA 与 `navigator.platform`、窗口与屏幕。

用真内核在容器里验证过：出口报日本 → 浏览器里 `navigator.language`、`languages`、Intl 区域、时区全是日本的一套；
出口报德国（小写代码）同理；关掉跟随用画像里的；表里没有的国家只改时区；国家给的是全名时不拿来查表。

### 4.15 Firefox 类内核（Camoufox）

内核分两类（4.12）。这一节是 Firefox 类怎么启动、能做到什么。**全部是用真实的 152.0.4-beta.30 在容器里量出来的**，
不是照上游的说明写的。

**启动**（`crates/host/src/firefox.rs`）

- 不需要 Playwright / Node / Python：直接起 `camoufox-bin -profile <目录> -no-remote`，指纹经环境变量
  `CAMOU_CONFIG_1..n` 里的一份 JSON 给（Windows 上每段 2047 字符，其余 32767；非 ASCII 写成 `\uXXXX`）。冷启动 1–3 秒。
- UA 由平台 + 内核版本生成，`rv` 永远等于内核的主版本。不给配置时它的 UA 里带着 "Camoufox"，所以这一项永远要给。
- 代理写进 profile 的 `user.js`，指向本机的代理桥，`socks_remote_dns` 开着：实测上游代理收到的是没解析过的域名。
  账号密码不进 `user.js`，也不进命令行。每次启动重写（桥的端口每次不一样）。
- 调试协议是 **WebDriver BiDi**（不是 CDP）。实验室的采集器（`bidi.rs`）在一个单独的沙箱域里跑和 Chromium 类同一段采集脚本；
  连着会话时页面自己看到的 `navigator.webdriver` 仍是 false。采完就结束会话。
- Windows 上加 `-wait-for-browser`：`firefox.exe` 默认是个启动器，拉起浏览器后自己就退了，Host 会以为浏览器已经关了。
  **这一条没法在这里验证**（Playwright 也是这么起的），要在 Windows 真机上确认。
- 不接受额外启动参数，不加载 Chromium 扩展，不设默认搜索引擎：这三样都是 Chromium 的机制。
- 名额、运行租约、心跳、独占锁、停止时归还，和 Chromium 类走的是同一段代码。

**能按环境给的**（Chromium 类给不了的加粗）

| 项 | 怎么给 | 实测 |
|---|---|---|
| UA、platform、oscpu、核数 | 配置 | 生效 |
| **屏幕宽高、可用区、色深** | 配置 | 真实屏幕 1600×900，网页看到 1920×1080 |
| **缩放** | Firefox 自己的 `layout.css.devPixelsPerPx` | `devicePixelRatio`、`resolution` 媒体查询、`screen` 三处自洽。Camoufox 自带的 `window.devicePixelRatio` 只改 JS 取值，媒体查询对不上，不用它 |
| 窗口 | 配置 + `-width/-height` | `outer/inner/clientWidth/宽度媒体查询` 自洽。必须显式给，否则默认 1280×1040 会比伪装的屏幕还大 |
| **显卡厂商和渲染器字符串** | 配置 | 真实值 Mesa/llvmpipe 被换成配置值 |
| 时区、语言、Intl 区域、Accept-Language | 配置（`locale:all`） | 整套对上，不需要 Chromium 类在 Linux 上那个环境变量 |
| **字体名单** | 按平台给：包里自带三套真字体文件（Windows 145 个、macOS 357 个、Linux 144 个，来自上游，MIT） | 枚举和量宽度都对得上 |
| **字体间距噪声** | `fonts:spacing_seed` 跟着环境种子 | 同一个种子跨重启稳定，换种子就变 |

**字体这一项为什么只有 Firefox 类有**

Chromium 类跑的是**原版 ungoogled-chromium，启动前逐字节核对哈希**——改过一个字节就拒启。
这是我们卖的东西，同行没有。代价是这个二进制里没有字体相关的能力：它带着
`fingerprint-brand`、`fingerprint-platform`、`fingerprint-screen-width` 这一串开关，
**唯独没有字体开关**；`FONTCONFIG_PATH` / `FONTCONFIG_FILE` 实测对它完全无效
（`fc-match` 认得 Segoe UI，浏览器里量出来仍是 monospace 基准值）。
往页面注 JS 能做到，但会被 `getOwnPropertyDescriptor` 和 `toString` 查出来，这条不走。

同行的做法是统一的：**全部自建补丁内核**。Multilogin 的 Mimic 明说字体值在二进制内部设定、
页面脚本之前生效、不注入任何东西；AdsPower 和 GoLogin 的 Orbita 同样是引擎级，
Orbita 还专门做了 Mac 字体伪装。没有一家用原版 Chromium。

所以产品上按**双引擎分工**（和 Multilogin 的 Mimic + Stealthfox 是同一个结构）：

- **Chromium 类的平台锁成本机**，界面上不给选，直接指路到 Firefox 类。这样不可能造出
  「本机 Windows、画像说 macOS」这种一查字体就露馅的环境。
- **跨系统画像走 Firefox 类**（Camoufox，补丁内核 + 三套真字体，开源可审）。

**还没做的：同一台机器上所有 Chromium 环境字体名单一样，可以被用来互相关联。**
不自建内核补不了。Multilogin 自己的文档也写着「两个画像显示同一个字体哈希是正常的」，
AdsPower 把「自定义字体名单」当增值项——市场把这条当可接受。需要强隔离就用 Firefox 类，
它的 `fonts:spacing_seed` 每个环境不一样。

**路线图：自建 Chromium 补丁内核。** 触发条件是字体或别的引擎级维度成了实际的拒登原因。
代价要说清楚：放弃「哈希对得上上游发布」这个卖点，并且要长期跟着上游版本自己维护构建——
那是一个量级的事，不是一个切片。

**工作台这一侧**

- 新建环境时先选内核的类，再在这一类里挑版本；建好之后只能在同一类里换版本。
- Firefox 类的屏幕、缩放、显卡、核数**来自同一台真机**（`src/lib/firefox-devices.json`，115 台，取自 Camoufox 项目收集的
  真实设备，MIT 许可），成套抽、成套换，界面上不能单独改其中一项。
- **只给这台显示器上用得了的设备**：缩放是真的缩放，2 倍缩放的设备在一块 1920 的显示器上窗口只能到 960 宽，所以不列出来。
  窗口要同时放得进环境自己的屏幕和这台显示器（按缩放折算），启动前再收一次。
- 这一类的环境页没有「启动参数」页签、默认搜索引擎和扩展：那三样是 Chromium 的机制。
- 一致性检查按类区分：Firefox 类核对 UA 里的版本就是正在跑的内核、实测的屏幕 / 缩放 / 显卡就是画像里那一套；
  没有 `deviceMemory` 这一项（Firefox 没有这个接口）。这台电脑上 WebGL 不可用时给提醒。

**做不到的，以及为什么**

- **Canvas 不加噪声，同一台电脑上所有环境的像素级 Canvas 指纹相同。** 上游 2026-04-14 把噪声补丁整个删了
  （提交 "Disable Canvas Noise"）：像素噪声本身能被识别。`canvas:seed` 现在是个没人读的键，我们不写它。
  同行的做法：Multilogin 的 Canvas 默认就是 Real（不加噪声），Dolphin 建议留 real；AdsPower、Octo 默认加噪声并提供"真实"。
  要 Canvas 噪声的用户用 Chromium 类。
- **`toDataURL()` 的哈希每次会话都变、像素不变。** 这不是 Camoufox 的行为，是 Firefox 152 自带的基线保护
  （往 PNG 里加一个随机的 `deBG` 块）。真实的 Firefox 用户都这样，所以不去关它。
  （实测 `privacy.fingerprintingProtection.overrides = "-CanvasRandomization,-EfficientCanvasRandomization"` 能关。）
- 包大：Windows 约 490 MB，解压后约 1.2 GB；单窗口内存约 640 MB。上游自己标的是 beta，所以三个平台都在预览通道。

### 4.16 同步密钥：端到端加密的那把钥匙怎么到另一台电脑上

用户要做的只有三件事：开启时保存一次恢复码；换电脑时在旧电脑上点一下「允许」并核对 6 位数字；手边没有旧电脑时输一次恢复码。
平时不输任何口令——加密用的数据密钥在系统钥匙串里（4.4）。

```
新电脑 ──公钥──> 服务器 ──> 旧电脑看到它，和一串 6 位数字
        用户在两台电脑上核对数字一致 → 旧电脑用新电脑的公钥把密钥包起来
新电脑 <──服务器只是转交这份包装──┘   拆开、收下
```

- 每台设备一对 X25519 密钥，私钥在系统钥匙串（`sync-device-key`），公钥交给服务器。
  包装用 ECDH + HKDF + AES-256-GCM，派生时把两边的公钥都算进去：换了收件人就得到另一把包装钥匙。
- **服务器拆不开任何一份包装**，它只存：密钥编号、给每台设备的那一份、恢复码那一份、每台设备的公钥。
- **服务器换掉公钥也没用**：那 6 位数字是公钥的摘要，两边各自算。数字对不上，用户不会点允许；
  就算点了，旧电脑在包装之前还会自己再核一遍（`SYNC_DIGITS_MISMATCH`）。
- 恢复码 20 个字符分 4 组，不含容易看混的字符（0/O、1/I/L），Argon2id 派生后包住同一把密钥。
  只显示一次，界面上不勾"我已经保存好了"就过不去。抄的时候大小写和横线都不计较。
- **收下别人的密钥时会先把本机已经加密的东西换过去**：用旧钥匙解出来、用新钥匙写回去，再换钥匙。
  所以接上同步之后，这台电脑原先存的代理密码照常能用。
- 用恢复码找回之后，这台电脑会自动登记成一台可信设备，下次换电脑可以从它批准。
- 关掉同步：服务器上的包装和密文删掉；本机的数据密钥不动，代理密码照常能用。

用两个真的本机服务（两台电脑）对着真的云端验证过 22 项：开启、恢复码不在服务器上、没被批准时收不下、
旧电脑看到新电脑和数字、**把公钥换成别人的就拒绝批准**、批准后两台是同一把密钥、本机已存的密码跟着换完还能用、
第三台电脑用恢复码找回（大小写和空格都认）、关掉同步后本机密码还在。
界面这一侧也走通了：开启 → 保存恢复码（不勾不让过）→ 另一台出现在待批准里并显示同一串数字 → 允许 → 对方收下。

### 4.17 环境和代理的同步：上云的全是密文

开了同步之后，环境和代理的配置加密后才上传。**服务器看得到的只有**：属于哪个账号、是环境还是代理、编号、第几版、
密文多大、什么时候改的。里面是什么，它不知道。

- 每一条用数据密钥派生出的**子密钥**单独加密；附加认证数据里绑着账号的密钥编号、类型、编号和版本。
  服务器把 A 的密文换给 B、拿旧版本冒充新版本、或者用换过的密钥冒充，客户端都解不开。
- **推**：本机每改一条，版本加一并记成"等着上传"。删掉的留一个墓碑，另一台电脑才知道是被删了，
  而不是它那边新加的。
- **拉**：云端比本机新的才收；本机更新的留着本机的。
- **两台同时改同一条**：服务器按版本挡下后到的那一次（`stale`），那台电脑在同一轮里收下服务器上的版本，
  两边立刻一致——先推上去的那次生效。小配置用最后写入者胜是明确的，不做三方合并。
- **代理密码也同步了**（团队功能要求的）：它用大家共用的那把钥匙加密之后才上云，服务器解不开；
  到了另一台电脑上仍然只进不出——界面永远读不回明文，启动时由本机服务自己取用。
  不这样做，团队里的操作员就永远打不开带认证的代理（他没有密码，又不许填），
  这个最常见的场景直接不可用。
- 时机：登录后一次、开着工作台每分钟一次、切回窗口时一次、设置页「立刻同步」一次。
  推之前先把界面上还没落盘的改动写完，免得刚改的那一笔被漏掉。
- 换密钥（被别的设备批准、或者用恢复码找回）之后，本机所有东西会重新用新密钥传一遍；
  暂时解不开的条目不会覆盖本机的，界面会提示"重新取一次密钥"。

两台真的本机服务对着真云端验证过 12 项：推、拉、改名、新增、删除跨机生效、两台同时改之后一致、
关掉同步后本机数据还在。**直接查服务器的数据库**：4 条记录里搜不到环境名、代理地址、代理密码任何一个词。
界面这一侧：开启同步 → 自动上传 → 另一台批准后拉到两个环境 → 对方改名后点「立刻同步」就看到。

### 4.18 登录态的同步：换台电脑不用重新登一遍

这是同步里唯一"大"的东西，所以走对象存储（R2 / 任何 S3 兼容的），不走数据库。
**上传之前在本机加密**，服务器和对象存储都只见得到一团密文。

- **什么时候导出**：停止环境的那一刻，在关掉内核之前。Chromium 类走 CDP `Storage.getCookies`，
  Firefox 类走 BiDi `storage.getCookies`；两边都拿得到 HttpOnly 的那几条——正是登录态所在。
  导出的内容按统一格式存，两类内核之间互转（`sameSite`、`expiry` 这些字段的写法不一样）。
- **什么时候放回**：启动环境、内核起来之后、用户看到页面之前。
  只有**云端那一份比本机新**才放回去，否则不动本机的。放回的条数会回给工作台（`cookiesRestored`）。
- **怎么加密**：数据密钥派生出的子密钥，AES-256-GCM；附加认证数据里绑着密钥编号、环境编号和版本号。
  换个环境的密文、拿旧版本冒充新版本、或者换一把密钥，都解不开。压缩在加密之前（zlib），
  解压有 32 MiB 上限，防的是压缩炸弹。
- **服务器怎么给地址**：客户端说"我要传这个环境、这一版、多少字节"，服务器签一个 **15 分钟、只对这一个对象、
  只对这一个动作**（PUT 或 GET）的临时地址。签名是自己写的 SigV4，没有引 AWS SDK。
  对象名是 `u/<账号>/cookies/<环境>`，每一段单独转义，`..` 这种直接拒签——一个账号翻不到另一个账号的目录里。
  服务器记的只有：属于谁、哪个环境、第几版、多少字节。密钥和明文它都没有。
- **上限**：单个环境 5 MiB、20000 条。超了就不传，停止照常完成——登录态的本机副本不受影响。
  管理员在后台填对象存储的密钥（和支付密钥一样是封存的，回显只给末几位），**不走环境变量**。
- **免费档不含同步**（`PLAN_NO_SYNC`），Solo 档起才有。
- **「只留在这台电脑上」**：环境上的一个开关。打开之后既不导出也不放回，并且**下一次同步会把云端那一份删掉**。
- **没上云的**：localStorage、IndexedDB、浏览记录、内核里存的网站密码、还有代理密码（4.17）。
  换电脑之后购物车这类东西会是空的，登录态在。这一版就做到这里。
- 传不上去不影响停止：版本号已经记下，下一次同步会补传；日志里留一行，不静默吞掉。

两台真的本机服务对着真云端 + 真对象存储验证过，两类内核各走一遍（13 + 9 项）：
管理员配置对象存储、后台不回显密钥明文、免费档被拒、A 登录站点、停止时上传、
云端记到的是这个环境、B 拉到环境配置、**B 启动时放回 2 条（含 HttpOnly 的会话 Cookie）、站点认它已经登录**、
改成「只留在这台电脑上」之后云端那一份被清空。
**直接把对象存储里那个对象打印出来**：251 字节，搜不到会话令牌、也搜不到任何一个 Cookie 名。

签名这一层另有单测覆盖：地址里不含密钥、同样输入签出同一个地址、换动作/换账号/换时间签名都变、
有效期太短太长都拒签、`..` 拒签。以及对着真 MinIO 验过：过期的地址 403、改一个字符的签名 400、
拿 A 的地址去读 B 的对象 404。

### 4.19 团队：成员、角色、按环境发钥匙

**"没分配给你"是解不开，不是不发给你。** 每个环境自己一把随机钥匙（`sync_slots`），
所有者和管理员的电脑用团队密钥解开它，操作员的电脑只收到服务器转交的、
用他自己公钥包着的那几份（`sync_grants`）。服务器两种包装都拆不开。

- 移除成员：可以顺手把他手上的环境转交给接手的人；他解得开的那几个槽位标成"该换钥匙"，
  由所有者的电脑在后台换掉——**只动那几个环境**，别的环境和别的成员一个字节都不用重传。
- 换钥匙时配置立刻重传（本机就有明文），登录态下载后用新钥匙封回去；
  拿不到旧钥匙就删掉云端那一份，宁可让它消失也不留着旧钥匙解得开的密文。
- 批准设备时把对方公钥**钉在本机**。之后自动发钥匙只认这一份：服务器把公钥换成自己的就不发，
  等用户重新核对数字。不做这条，自动轮换就是个后门。


**授权的单位是文件夹，不是单个环境。** 给一个操作员开一个文件夹，里面的环境他全都看得到，
之后新建进去的也自动跟着——按单个环境分配时，每建一个新环境都得回来再分配一次，
而漏掉的那次没人会发现。同行（AdsPower 的授权分组、GoLogin 的指定文件夹、Dolphin 的分享文件夹）
都是这个形状。跟着多数派**不做**：嵌套文件夹、每文件夹单独的权限级别、一个环境进多个文件夹。

- 文件夹是服务器上的真对象（`folders` 表，环境带 `folder_id`），不是环境上的一段自由文本——
  授权不能挂在一个打错字就变成新分组、改个名权限就飞了的字段上。
- 每个环境必须属于且只属于一个文件夹；没给或给了不存在的就落进「默认」（`pickFolder`，有单测）。
  否则它就成了谁都看不见、却还占着名额的孤儿。
- **钥匙模型一字不改**：还是每个环境一把，文件夹只是算出"该给谁发哪几把"的规则。
  整套权限只经过 `AssignedProfiles` / `AssignmentsOf` 两个函数（`store/folders.go`），
  发钥匙、收钥匙、标记过期都在它们下游，一处都没动。
- 环境换文件夹 = 权限变化：`putProfile` 前后各算一次每个操作员看得到什么，少掉的走 `revokeGone`
  ——收回他各台电脑上的授予、把那把钥匙标成要换。删文件夹同理，里面的环境回到「默认」。
- **已经同步到他电脑上的那一份收不回来**，界面和文档都如实写着。收回之后服务器不再授权他启动、
  不再发新内容、钥匙换掉——能做到的是这三件。

Team 档是 6 个人（含所有者），**每人 1 台电脑**。成员用自己的账号登录工作台，按角色使用团队的环境。

- **三个角色**，含义只在一处定义（`store/members.go`），别处只做判断：
  - `owner` 一个团队一个，付费、增减成员、开文件夹都归他。
  - `admin` 管环境、文件夹和授权，不能动订阅，也不能增减成员。
  - `operator` 只能打开开给他的文件夹里的环境。
- **邀请**：填上对方邮箱，邀请信由我们发出去（SMTP 由管理员在后台配，密码封存入库，
  回显只给末几位；后台有「发一封测试信给我自己」）。**没配发信服务器也能用**——
  界面照样给出链接，由所有者自己发。链接 7 天有效、只能用一次，
  **数据库里存的是令牌的哈希**，事后连所有者自己也看不到原文，要重发只能重新生成。
  对方在 `/join` 设个密码就加入了，邮箱由邀请决定、改不了。
  团队有个名字（默认是所有者的邮箱，可改），它出现在邀请信和加入页上，供对方认人。
  发信只用标准库 `net/smtp`：收件人和主题里带换行的一律不发（防信头注入，有单测），
  账号密码只在 TLS 或 STARTTLS 之后才发——服务器不加密就宁可发不出去。
  席位算的是"已在团队里的人 + 还没用掉的邀请"，两头都在同一个事务里数，两个人同时接受也超不了。
- **按人分环境**：所有者给每个操作员勾环境。**没勾的，服务器连密文都不下发**——
  不是客户端自觉不显示。要说清楚的是：这是**服务器不发**，不是密码学隔离，
  团队共用一把数据密钥（4.16 那一套原样沿用，所有者的电脑批准成员的电脑，还是核对 6 位数字）。
  代理是例外，照单全发：服务器看不见环境里绑的是哪个代理（那是密文）。
  代理密码跟着共用的那把钥匙一起给他——**能用，但读不回明文**。
- **操作员碰不到的东西**，两边各拦一道：
  本机服务按一张表拦（`operator_blocked`，有单测盯着正反两面），服务器按角色再拦一次。
  拦的是：新建/修改/删除环境和代理、代理密码、环境名额登记、开关同步、批准设备，以及导出环境包。
  **角色记在本机**（`store.db` 的 `meta` 表），所以拔掉网线再来导出，答案还是拒绝。
- **不能说"员工带不走店铺资产"**，这句话是假的。他坐在自己那台电脑前：
  内核的调试端口开在本机且没有鉴权（那还是我们卖出去的功能，见 4.10），
  直接拷 `user-data` 目录也一样——同一个操作系统账号，Windows 的 DPAPI、macOS 钥匙串、
  Linux 的密钥环都拦不住本人。**任何产品都做不到**，所以我们照实说：
  能拦住的是顺手为之，拦不住的是有意为之；真要断掉，去平台上点「退出所有设备」。
- **移出成员**：他的电脑立刻解绑（令牌当场失效）、密钥包装删掉（换台电脑也换不到钥匙了）、
  分配收回；他的账号还在，只是回到一个属于他自己的免费组织。
  **他电脑上已经解开过的那一份收不回来**——移除的确认框和这份文档都照实说，不粉饰。
  轮换团队密钥（换一把新的重加密全部数据）是下一步，还没做。

三台真的本机服务（所有者 + 操作员 + 断网重来的那一台）对着真云端验证过 37 项：
非 Team 档不能邀请、角色只能是管理员或操作员、邀请只能用一次、乱填的邀请码、
操作员看不到成员管理也邀不了人、**操作员建不了环境（本机拦一道、服务器再拦一道）**、
开不了同步、没分配之前一个环境都看不到、分配之后只看得到那一个、没分配的启动被拒、
分配了的能启动而且**用完登录态照样传回团队**、**他开着的时候收回分配、一分钟内那个环境被停掉并给出原因**、
导不出、**断网也导不出**、移出后他的电脑立刻失效、账号还在。
**直接查数据库**：服务器上两个环境的密文都在，操作员那台只拿到了分配给他的那一个。

**指纹章算法两仓库各一份，用同一组黄金向量钉死。** 工作台（`src/lib/glyph.ts`）和官网
（`web/lib/glyph.ts`）是两个有意解耦的仓库，合不成一个文件；两边各有一条同名测试，
对同一个种子断言同一段路径。任何一边改了算法，另一边的章就对不上，测试会先叫——
和配对数字的 Rust/Go 共用测试向量是同一个办法。

**官网账号页每块面板各自一层错误边界**（`components/boundary.tsx`）：一块出错只把那一块换成一句话，
页面其余照常；另有路由级的 `app/error.tsx`，不再落到 Next 自带的那页英文错误页。
这是「成员没分过环境时整页打不开」那个 bug 的第二层保险——第一层是服务器不再发 null。
**边界本身没有自动化测试**：站点没有组件测试环境，只靠构建通过和代码审阅。

### 4.20 操作日志

谁什么时候在哪台电脑上开了哪个环境，以及成员和钥匙的变动。**记在服务器上**——
记在本机的日志，老板看不到，也没法信。

- 记这些：打开/关闭环境、打开被拒（被别人占着、并发满了）、被另一台接管、
  新建和删除环境、电脑登录和解绑、邀请/加入/改角色/移出团队/分配环境、
  开启同步、批准电脑、换钥匙、改档位。每条带操作人、哪台电脑、IP 和时间。
- **环境里做了什么，我们看不到也不记**——那些是密文。这条日志记的只有我们本来就要经手的动作。
- **看得到的是所有者和管理员，操作员看不到**：他看得到的话，就知道自己有没有被盯着。
- **没有删除接口**。能被删掉的审计日志没有意义。保留 90 天后自动清理
  （同行里 Octo 是 30 天；店铺出事往往一两个月后才发现，所以我们给得长一点）。

验证过 10 项：改档位/邀请/加入都记下了、带中文说法和操作人对象、带 IP、保留天数、
操作员拿到 `ROLE_FORBIDDEN`、没登录拿到 `UNAUTHENTICATED`、按动作过滤。

### 4.21 地理位置

时区和语言早就跟着代理出口走了，定位不跟就是个一查就发现的矛盾。环境的指纹页上四选一：

| 选项 | 行为 |
|---|---|
| **跟着代理出口走**（默认） | 报出口所在地。没配代理、或查不到出口坐标就什么都不做——不编一个坐标出来 |
| 自己填经纬度 | 不管代理在哪都报这个 |
| 禁用 | 网页根本要不到位置，和用户点了"拒绝"一样 |
| 用真实位置 | 不动它 |

两类内核走的路不一样，**Firefox 类那条更彻底**：

- **Firefox 类**：坐标和禁用都写进启动配置（Camoufox 原生的 `geolocation:*` 键、
  `geo.enabled`），和时区、语言同一条路——**启动前生效，对所有标签页都算数**。
- **Chromium 类**：启动后用 CDP 补。坐标走 `Emulation.setGeolocationOverride`，
  **这个域按页面生效**，所以除了启动时那一刀，还给每个环境留一条 CDP 连接盯着：
  新页面用 `Target.setAutoAttach` 配 `waitForDebuggerOnStart` 挂上来时是暂停的，
  设完坐标再放行，**用户新开的标签页在跑第一行 JS 之前就已经盖好**。
  禁用走 `Browser.setPermission`，那个是浏览器级的，所有标签页都算数。
  环境一停，这条连接跟着收掉。

走的都是内核自己的域，不是往页面注 JS——注 JS 会被 `getOwnPropertyDescriptor`
和 `Function.prototype.toString` 查出来，这两条不会。权限状态保持"询问"，
和真实浏览器一样：我们只保证用户点了允许之后，拿到的位置和出口一致。

盯新标签页那条路有个自身风险：**页面是被暂停住等放行的，放行漏一次就卡死用户的
一个标签页**。所以放行做成了无条件的——设坐标失败也照样放行，连接断了内核会自己放掉
所有等着的页面。单测专门盯这条：不管要不要设坐标，放行命令必须存在、必须排在最后。

**一个还没解决的**（写在这里，不在界面上含糊过去）：

1. **禁用时 `permissions.query` 报的还是 `prompt`**。真实浏览器里设成"不允许"时
   它会是 `denied`。CDP 的权限设置改了行为、没改上报的状态。功能对了，状态还差一口气；
   彻底解决要在启动前写 `Default/Preferences` 里的内容设置。

实测（真内核，9 项）：出口在柏林时报柏林、**新开一个标签页报的还是柏林、而且没被卡住**、
用真实位置时不覆盖、自己填东京就报东京、禁用时网页拿到"被拒"、
Firefox 类的坐标确实写进了启动配置。新标签页那两项验过反面——把监督器摘掉就挂
（问不出位置），装上才过，不是一条两边都绿的空测试。

### 4.22 批量执行

选一批环境，一次对它们做同一件事。在环境列表里勾选，表格上方出现操作条。

| 项 | 怎么做的 |
|---|---|
| 选择 | 表头的复选框只全选**当前筛选出来的**行；换搜索、进出回收站都清空选择——勾着看不见的东西最容易出事 |
| 动作 | 只有批量启动和批量停止。一次最少 1 个、最多 200 个 |
| 启动选项 | 启动后打开的网址（可留空）、同时启动数 1–8、重试次数 0–5 |
| 重试 | **只对"等一下就好"的原因重试**：额度满了、环境正被另一台电脑开着、暂时连不上服务器。内核哈希不符、代理连不上这种，重试多少次都是同一个结果，直接记下来 |
| 同一代理不扎堆 | 同一个代理出口同时最多 2 个、两次之间至少隔 30 秒。等待时条目上写着还要等几秒，不会干等着像卡死 |
| 没登记过的环境 | 自动登记一次再重试——**和单个启动一模一样的行为**。同一个动作不能有两套规矩 |
| 进度 | 列表上方的常驻面板：一行一个环境、状态、失败原因和重试次数，顶部是「3 / 12 已完成」和取消按钮 |
| 取消 | 已经在跑的那几个跑完，还没轮到的标成"已跳过" |
| 记录 | **只留最近 10 次，在本机服务的内存里，关掉工作台就没了**。界面上如实写着这句话。要长期记录看官网的操作日志 |

**不做定时任务。** Host 是工作台的随行进程，关掉应用它就没了；在这种形态下提供"定时"是骗人的。
要做得先决定常驻后台，那是另一件事。

操作员能批量启停**分配给他的**环境，和单个启停一条规矩：批量走的也是同一条启动路径，
服务器照样按分配拒绝。团队套件里专门有一条盯着这个——多选是最容易"顺手把没分配的也勾上"的地方。

实测：批量接口 8 项（真内核，三个环境启停、并发排队、操作日志）；工作台界面 11 项
（真内核 + 真 Host：全选、换搜索清空选择、选项展开、发起后选择清空、进度到 3/3、
列表里三个真的在跑、批量停止后一个不剩）。

### 4.23 自动化：流程编辑器与执行器

一串按顺序执行的步骤，选一批环境同时跑。**AdsPower 是标杆**（16 个网页动作 + 键盘/等待/取数 +
7 个流程节点，还能录制），Dolphin 是积木式场景，GoLogin、Multilogin 只给 API。我们取 AdsPower 的核心子集。

**形状**

- 流程是一类新的同步文档 `workflow`，和代理一样走共用的那把钥匙：团队资产，全员可见；
  操作员能跑、不能改。云端只有密文，零知识不变。
- **10 个步骤**：打开网页 / 点击 / 输入 / 按键（Enter、Tab、Escape）/ 滚动 / 等待元素出现 /
  等待 N 秒 / 提取文本（存到变量）/ 条件跳转（变量 包含·等于·非空 → 跳到第 N 步或结束）/
  循环（第 A 到 B 步重复 N 次）。参数里可写 `{{变量}}`。每步一个失败策略：重试 N 次 / 跳过 / 终止。
- **扁平列表 + 跳转，不做嵌套块**：编辑器就是一张可增删上下移的步骤表，不做画布、拖拽、录制。
  **循环节点放在循环体之后**——走到它就回头再跑一遍，范围必须整个在它前面；写在后面就当没有循环，
  不报错、不卡住。条件跳转可以写成死循环，所以一个流程最多执行 5000 步。

**执行器（`crates/host/src/workflow.rs`）**

- 解释器和协议分开：`run_with` 只认 `Driver` 这一层，条件、循环、失败策略、变量替换、取消
  全部用一个假驱动在单测里过（6 条），不用起浏览器。
- **Chromium 类只用 DOM 和 Input 域**定位、点击、输入，**全程不开 `Runtime.enable`**——那是 CDP
  自动化最常见的暴露点，Puppeteer 就栽在这；只有「提取文本」用一次不 enable 的 `Runtime.evaluate`。
  **老实说：这条是行业共识，不是我们实测出来的。** 经典探测器（给 Error.stack 挂 getter 再
  console.debug）在这个内核的无头模式下两种模式都不触发，分不出差别。设计照旧，因为它的暴露面严格更小。
- **Firefox 类走 BiDi**：`locateNodes` 定位、`performActions` 点击敲键、带沙箱的 `script.evaluate`
  提取。跑完必须 `session.end`——BiDi 同一时刻只许一个会话，不收掉实验室采集就进不来（套件里有一条盯着）。
- 触发复用批量执行：新动作 `workflow` = 启动 → 跑流程 → 按选项停掉环境（默认停）。进度就在批量面板里，
  每个环境显示「流程跑完，N 步」或「第 N 步失败：原因」。取消每一步之前问一次。

**不做（跟着"最小"）**：录制、执行 JavaScript 节点（用户自己往页面注脚本一查就露）、文件上传、
iframe、多标签页、定时（Host 是随行进程，理由同批量）。

实测（真内核，接口级）：Chromium 类 8 项——存流程、条件成立提前结束且没碰后面会失败的那步、
跑完按选项停环境、失败时说得出第几步和为什么、不存在的流程被拒；**Firefox 类 5 项，同一个流程
原样跑完**，之后实验室采集照常。
工作台界面（真内核 + 真 Host）9 项：侧栏进自动化页、新建流程、加三步、列表显示步数、
存进本机服务、环境列表里「运行流程」发起、进度面板报「流程跑完，3 步」。**这一轮抓到一个双轨**：
给批量启动补的"没登记过就自动登记"只判了 start，跑流程走同一条启动路径却享受不到——
已改成除 stop 之外都补登记。

## 7. 给开发的一句话

继续开发时，每做一个功能先问两遍：

> 客户装上安装包、在自己电脑点启动，这件事会不会发生？
> 这个东西，用户需要看到吗？

第一个问题答"不会"就别做进 1.0；第二个答"不需要"就别放进界面。
