# Enclave 交付说明

> 卖法和客户用法对齐 AdsPower / GoLogin / Multilogin 这一类：
> **官网下载桌面安装包 + 账号订阅解锁额度。内核跑在客户自己的电脑上。**
> 不是服务端开 Chrome、客户端只看网页。

更新于 2026-09-20。这份文件同时是**交付合同**和**当前进度**：
"已交付"一栏只写代码里真的做到的事，做不到的写在"未交付"。

## 0. 三个东西，别混

| 说的是 | 指什么 | 现在 |
|---|---|---|
| **代码签名证书** | Authenticode / Developer ID，证明安装包是谁发的 | 未购买，本轮明确不做 |
| **许可证** | 厂商签发给账号的订阅凭据，解锁额度 | **已实现**（Ed25519 签名，`apps/vendor`） |
| **开源许可证** | 内核的 BSD-3-Clause | 与上面两件事无关，公示在官网 |

### 1.1 客户拿到的

| 交付件 | 形态 | 状态 |
|---|---|---|
| 工作台安装包 | Windows x64 `.msi` | **可构建**（`scripts/windows-msi.ps1`），未做正式签名 |
| 工作台安装包 | macOS `.dmg` | 未做 |
| 内核 | fingerprint-chromium，按清单下载并校验 | 已实现，linux 稳定通道、win/mac 预览通道 |
| 官网 | 产品 / 套餐 / 下载 / 文档 / 账号 / 法律 | 已实现（`enclave-www`） |
| 账号与订阅 | 注册、登录、档位、设备绑定、离线宽限 | **已实现**（官网 + 工作台 + 许可证服务） |
| 文档 | 安装、账号、内核、环境、代理、实验室、导出、接口、安全 | 已实现（官网文档页） |

### 1.2 客户用法（1.0 必须是这条）

1. 打开官网，注册（免费档立即开通）。
2. 下载安装包，**核对 SHA256**，安装。
3. 打开本机工作台，登录。额度从账号同步：环境数、同时运行数、设备数。
4. 内核页一键准入：下载 → 校验压缩包 → 解压 → **记录实际可执行文件的哈希**。
5. 新建环境 → 配代理 → 锁定画像 → 启动。
6. **本机弹出独立内核窗口。** Cookie / 指纹 / 出口只属于这个环境。
7. 实验室采集的是该内核窗口，不是工作台自己的页面。
8. 换电脑：安装、登录、导入环境包（`.enclave.json`）。

失败必须拒启并显示原因码：`KERNEL_HASH_MISMATCH` / `KERNEL_UNTRUSTED_SOURCE` /
`KERNEL_CHANNEL_BLOCKED` / `SANDBOX_UNAVAILABLE` / `CDP_HANDSHAKE_FAILED` /
`HOST_UNAVAILABLE` / `VAULT_LOCKED` / `PROXY_PASSWORD_MISSING` / `PLAN_CONCURRENT_LIMIT` /
`SPAWN_FAILED` / `SANDBOX_DISABLED_BLOCKED`。
**禁止绿灯假 Running。**

### 1.3 明确不是交付物

- `npm run dev` / vite 预览
- 把工作台当网站卖、"客户打开你们的网页，Chrome 在你们服务器里"
- 把 `data/kernels/` 打进镜像分发
- 任何"保证过某站风控"的承诺

## 2. 商业结构

### 2.1 档位

| 档 | 环境数 | 同时运行 | 设备 | 本机 API | 价格 |
|---|---|---|---|---|---|
| Solo Free | 3 | 1 | 1 | 关 | 免费，注册即开通 |
| Solo | 50 | 3 | 1 | 只读 | 报价 |
| Pro | 200 | 8 | 2 | 完整 | 报价 |
| Team | 200 起 | 8 | 6 | 完整 | 报价 |

档位**只在一处定义**：`apps/vendor/src/license.js`。客户端只留免费档兜底
（`src/lib/license/plans.ts`），官网账号页从 `/api/plans` 取，都不再各抄一份。
窗口同步和团队席位尚未实现，所以不在表里；规格见 [TODO.md](../TODO.md)。
安装包不收费。内核安全更新对所有档位开放，不锁在高档。

**付费开通目前是人工的**：用户在官网账号页提交申请 → 运维用 admin 接口改档 →
客户端下次同步生效。还没接支付网关，这是已知缺口（见第 6 节）。

### 2.2 许可证怎么工作

```
官网注册/登录  ──cookie 会话──>  许可证服务
工作台登录     ──邮箱+密码──>   许可证服务  ──> 设备令牌 + 签名许可证
工作台之后     ──设备令牌──>    许可证服务  ──> 续签
```

- 许可证是 `v1.<base64url(payload)>.<ed25519 签名>`，公钥内置在客户端。
- payload 里写死了这台设备能用的上限；**客户端按 payload 执行，不按自己代码里的表执行**。
- `refreshAfter`（24 小时）到了就在线续签；`validUntil`（14 天）是离线宽限硬边界。
- 验签失败 / 过期 / 系统不支持 Ed25519 → 一律回落免费档，**绝不"姑且相信"**。
- 本机只存设备令牌，从不存账号密码。设备令牌只能换许可证和登出，改不了账号。
- 官网账号页可以解绑设备；解绑后那台机器续签时收到 `DEVICE_REVOKED`，本机登录立即清空。

额度在客户端强制。这是本地优先产品的固有边界：软件在用户机器上，足够熟练的用户
可以改本机状态。我们防的是"顺手就能白嫖"，不是"防住逆向"。真正靠服务端保证的
只有一件事：**没有厂商签名就拿不到任何高于免费档的许可证。**

## 3. 架构（发行形态）

```
客户电脑
┌───────────────────────────────────────────────┐
│ Enclave.exe (Tauri)                           │
│  ├─ 生成 32 字节 OsRng 令牌                    │
│  ├─ 启动 enclave-host（sidecar，带令牌）       │
│  └─ initialization_script 注入同一个令牌        │
│                                               │
│  ┌─────────────┐   Bearer 令牌                 │
│  │ React 工作台 │ ──────────────┐               │
│  └─────────────┘               ▼               │
│                      enclave-host 127.0.0.1    │
│                      准入 / spawn / CDP / 回收  │
│                               │ spawn          │
│                      fingerprint-chromium      │
│                      user-data 独立            │
└───────────────────────────────────────────────┘
        │ 仅登录与续签
        ▼
  许可证服务（HTTPS，只有账号和档位）
```

数据都在客户机：环境定义与画像在工作台数据目录，Cookie 在各环境
`profiles/env_*/user-data/`，代理密码在 AES-GCM 保险箱，内核在 `data/kernels/`。

## 4. 已交付（逐条可验证）

### 4.1 本机接口不再任人调用

之前：桌面壳用 `ENCLAVE_ALLOW_LOOPBACK_NO_AUTH=1` 启动 Host，CORS 是 `*`，
**任何网页都能 POST `127.0.0.1:17891` 启动环境、枚举运行态、改写环境的默认搜索引擎。**

现在（`crates/host/src/main.rs`）：

- 跳过鉴权的开关**整个删掉**，代码里不存在这条路径。
- 令牌是 32 字节 `OsRng`（之前是 `DefaultHasher(时间+pid)`，可枚举），文件权限 0600，定长比较。
- CORS 只放行工作台自身来源；其他 Origin 直接 403。
- `Host` 头必须是回环地址，挡 DNS rebinding。
- 端口可配，**地址不可配**：永远只绑 127.0.0.1。
- `/v1/health` 只回 `{ok:true}`，不再泄露内核版本和本机能力。

### 4.2 校验的是真正被执行的文件

之前：只校验下载的压缩包；解压目录里已有 chrome 就跳过解压，所以一个被替换过的
可执行文件会被直接沿用，界面还显示"已准入"。

现在（`crates/host/src/kernel.rs`）：

- 准入时**必然重新解压**，然后对可执行文件单独算 sha256，连同大小和修改时间记下来。
- 每次启动前核对可执行文件：本进程第一次做全量 sha256，之后比对大小/修改时间，
  任何一项对不上就升级成全量校验，不符 → `KERNEL_HASH_MISMATCH` 拒启。
- `status.json` 里记的"已准入"不再被无条件相信：文件对不上就改回错误态。
- 运行态里记录的 sha256 是可执行文件的哈希，不再是压缩包的。

### 4.3 内核通道会拦

清单里 `channel != stable` 的内核（当前 win-x64 / mac-arm64）需要用户在安全中心
明确勾选"允许使用预览通道的内核"，否则准入和启动都返回 `KERNEL_CHANNEL_BLOCKED`。
之前代码完全不看通道，只要有哈希就用。

### 4.4 代理密码进了保险箱

之前：`auth.password` 明文存在 localStorage，而官网文档写着"只存保险箱引用"。

现在：

- 主密码 → PBKDF2-SHA256(310k) → AES-GCM 密钥，密钥只在内存，锁定即丢弃。
- 磁盘上只有 salt / iv / 密文。没设主密码时**不保存任何密码**。
- 启动环境时若代理需要密码而保险箱锁着 → `VAULT_LOCKED` 拒启，
  不会静默地用一个没有密码的代理（那会直接以本机 IP 出网）。
- 锁屏是真的：解锁 = 用主密码解开保险箱，密码错就是错（之前任何输入都能解锁）。

### 4.5 账号与订阅真的通了

`apps/vendor` 零 npm 依赖（Node 内置 http / crypto / sqlite）：

- 注册、登录（scrypt 密码哈希）、会话 cookie、登录限流。
- 设备绑定与设备数上限；官网可解绑。
- Ed25519 签发许可证；订阅过期的账号**按免费档签发**，不会继续发 Pro。
- 升级申请与联系表单落库，运维用 `x-admin-token` 改档。
- CORS 只放行工作台来源，且只对 `/v1/*` 生效。

之前 `setMyLicenseFn` 允许任何登录用户把自己改成 Pro —— 那个接口和整套
better-auth / Postgres 脚手架已删除。

### 4.6 桌面端不再依赖打不出来的服务端

之前工作台是 TanStack Start SSR 应用：登录和额度走 `createServerFn` → 同源 `/api/*`。
MSI 是纯静态包，没有 `/api`，所以**装完之后登录必然失败**，代码里甚至有注释承认这点。

现在工作台是纯前端 SPA：只跟本机 Host 和许可证服务说话，开发和打包后同一条链路。
顺带删掉了模板残留：`grok-pwa` 插件与其两万行测试、`app-data` 连接器、
`multiplayer/p2p.ts`（570 行零引用）、better-auth / PGLite / Neon / Nitro / migrations、
以及三份官网拷贝里的两份。

### 4.7 Tauri 壳收紧

- capabilities 从 `shell:allow-spawn` + `shell:allow-execute` 收到只剩 `core:default`
  —— 页面不再有任何执行外部程序的能力（sidecar 由 Rust 侧启动）。
- CSP 从 `null` 改成实际策略。
- 窗口在 Rust 里创建，注入令牌的脚本先于页面任何代码执行。

### 4.8 环境导出 / 导入

`.enclave.json` 带走环境定义、画像、代理和搜索引擎配置。
**Cookie、缓存、浏览记录不在里面**，界面和文档都写明。
代理密码只有填了导出口令才会带上，用该口令单独 PBKDF2+AES-GCM 加密。
导入时受当前档位环境数上限约束。

### 4.9 界面

官网与工作台统一到一套设计系统（[DESIGN.md](../DESIGN.md)，源自 ClickHouse 的
近纯黑 + 电光黄）。所有 token 只定义一次，两边共用。

同时按"用户不需要看到的东西一律不出现"清理了界面：

- 删掉引导里的"选择档位"（那等于让用户自己发许可证）。
- 原来的 `apiEnabled` 开关打开后什么也不会发生；现在它背后是真的本机 API（见 4.10）。
- 删掉工作台里的出口 IP 探测（它探的是本机网络，不是环境出口，会让人看错；
  而且那是一个发往第三方的请求）。
- 内部状态词（`admitted` / `hash_mismatch`）换成中文，并给出下一步怎么做。
- 删掉"没有回滚版本"这种给不出原因的灰按钮、空的选择框、模板遗留页面。

### 4.10 本机 API（给脚本用）

同一个 Host、同一个端口，不是第二个服务。路径 `/api/v1/*`，凭据是独立的 API 令牌
（Host 用 OsRng 生成，0600 落盘，可重置），和工作台令牌互不通用。

- 默认关；免费档开不了；Solo 只能 GET；Pro / Team 可以启动和停止。
- 带 `Origin` 头的请求一律拒绝 —— 脚本从不带，网页必然带。
- 工作台把每个环境的启动参数推给 Host，**只放内存**（里面有带密码的代理地址）。
  代理密码在锁着的保险箱里的环境不推，脚本因此无法让它以本机网络出网。
- 同时运行上限对 API 同样生效；启动走的是和工作台同一个 `run_start`。

在真实运行的 Host 上用 curl 验证过 13 种情况，并在真浏览器里走通了
「登录 → 验签 → 开启 → 用界面上的令牌以脚本身份列出环境」。

### 4.11 测试与 CI

之前：Rust 测试 0 个，没有 CI，`npm test` 跑的基本是模板管道。

现在：

- `cargo test -p enclave-host`：flag 白名单（默认拒绝、调试端口不能离开回环、
  隔离破坏类 flag 拒绝）、令牌长度与定长比较、来源名单、API 档位权限、进程组信号只打到目标（不会再出现 `kill -1`）、环境 id 不能逃出数据目录。
- `npm test`：许可证验签 6 个用例，包含"改档位但不重新签名"的伪造尝试。
- `apps/vendor` `npm test`：签发/验签、换公钥失败、改一字节失败、过期降级、宽限期。
- `.github/workflows/ci.yml`：三块分别构建测试，外加"二进制和运行时数据不得进仓库"的检查。

## 7. 给开发的一句话

继续开发时，每做一个功能先问两遍：

> 客户装上安装包、在自己电脑点启动，这件事会不会发生？
> 这个东西，用户需要看到吗？

第一个问题答"不会"就别做进 1.0；第二个答"不需要"就别放进界面。
